# CHANGELOG

All notable changes to this project are recorded in this file.

## Unreleased

- **$NOPREFIX**: Programs starting with `$NOPREFIX` may write QB64 names without their `_` (`Option Explicit`, `FullScreen SquarePixels`, `RGB32`, `Display`), as in QB64.
- **_FULLSCREEN**: Added `_FULLSCREEN [{_STRETCH|_SQUAREPIXELS|_OFF}][, _SMOOTH]` and the `_FULLSCREEN` function.
- **DIM AS type list**: QB64's `DIM [SHARED] AS type name, name...` declares every name with that type (it was a syntax error).
- **OPTION _EXPLICITARRAY**: Accepted; on its own it requires only arrays to be declared.
- **SYSTEM code**: `SYSTEM n` exits with status `n`, as in QB64.
- **Fixes**: `$RESIZE:OFF`, `:STRETCH` and `:SMOOTH` were run as a line label followed by a statement (a syntax error; only `$RESIZE:ON` worked). A fixed-length string (`DIM s AS STRING * 3`) after `DEFLNG` or another `DEFtype` was treated as a number. `CASE IS` no longer counts as an undeclared variable under `OPTION _EXPLICIT`.
- **_PRINTMODE (behavior change)**: Added QB64's `_PRINTMODE {_FILLBACKGROUND|_KEEPBACKGROUND|_ONLYBACKGROUND}[, handle]` and the `_PRINTMODE` function. As in QB64, `_PRINTSTRING` now fills the box behind its text with the `COLOR` background by default (it always left the background alone); use `_PRINTMODE _KEEPBACKGROUND` to draw text over graphics. `PRINT` follows the same mode, and each image and each new `SCREEN` starts with `_FILLBACKGROUND`. The paint, printstring, resize and graphics showcase demos use `_KEEPBACKGROUND`.
- **Printstring Demo**: `demo/printstring.bas` is now an animated showcase of `_PRINTSTRING`, `_PRINTWIDTH`, `_LOADFONT` and `_FONT`: an outlined, centered title, a gallery of system fonts (macOS or Linux, with missing ones listed as not installed), plain/bold/italic/underline styles, left/center/right alignment, translucent letters, a rainbow wave, a typewriter line and a scrolling ticker. `--selftest` saves `tests/printstring.png` and exits.
- **String Constants**: `CONST name = "text"` defines a string constant, usable without a `$` and inside procedures (it printed 0, and using it in a string expression was a syntax error). One `CONST` may define several constants (`CONST a = 1, b$ = "x"`).
- **EXIT DO with LOOP UNTIL / WHILE**: `EXIT DO` in a loop that ends in `LOOP UNTIL` or `LOOP WHILE` continues after the `LOOP` statement; it was a syntax error.
- **_LOADFONT (behavior change)**: Font handles follow QB64: loaded fonts are 32 and up and a font that cannot be loaded is -1 (it was 0, and the failure was printed to stderr). The optional style argument (`"BOLD"`, `"ITALIC"`, `"UNDERLINE"`; `"MONOSPACE"` and the like are accepted) works, `_FONT 8`, `14`, `16` (QB64's built-in fonts) select the default font, and `_FONT` used as a function returns the font in use. Removed debug output that every `_LOADFONT` printed to stderr, and a debug line printed when skipping a block `IF` inside a procedure.
- **Binary Strings in Functions**: `CVI`, `CVL`, `CVS`, `CVD`, `LEN`, `ASC`, `VAL`, `INSTR` and `_PRINTWIDTH` keep the zero bytes in their string argument; they stopped at the first one, so `CVS(MKS$(25))` was 0 and `LEN(MID$(a$, 3))` of binary data could be 0 (programs that keep numbers in strings with `MKI$`/`MKS$` could fail with "Division by zero").
- **IF ... THEN line**: A line number right after `THEN`, `ELSE` or `GOTO` in an `IF` (`IF x THEN 30`, `... ELSE 50`, `IF x GOTO 70`) jumps to that line; when the condition was true it was a syntax error.
- **NEXT with Several Variables**: `NEXT j, i` closes the inner loop and then the outer one (it was a syntax error). A loop that runs zero times now skips to the `NEXT` that closes it when the loops inside it end with a named `NEXT` (it could run past it).
- **DATA after Other Statements**: `READ` finds `DATA` after a colon or `ELSE` on its line, as in QBasic (it was "Out of DATA").
- **Line Continuation and Long Lines**: A line ending in ` _` continues on the next line, as in QB64, and program lines may be up to 1023 characters (lines longer than 255 were split in two when loaded).
- **Palette Colors Wrap**: In palette modes a color number keeps only the mode's low bits, as on the VGA (in SCREEN 12, -4 is color 12 and 20 is color 4); before, out-of-range colors used entries of the 256-color palette, so shading that dipped below 0 showed magenta.
- **OPTION _EXPLICIT**: Accepted and enforced as in QB64: before the program runs, every variable must have been declared in its scope (`DIM`, `STATIC`, `COMMON`, `CONST`, `SHARED`, a parameter or the `FUNCTION` name), or the program stops with "Variable not defined: name" (error 92).
- **_ROUND**: Added QB64's `_ROUND(x)`, rounding halves to even.
- **32-bit Colors in LONG Variables**: As in QB64, a whole number up to 2^32 - 1 stored in a LONG keeps its bit pattern, so `c& = POINT(x, y)` and `DEFLNG A-Z: c = _RGB32(255, 255, 255)` work (it was an Overflow). `POINT` and the `_RGB`/`_RGBA` family return whole numbers. Floating-point values outside LONG range are still an Overflow.
- **DEFtype and Parameters**: `DEFINT`, `DEFLNG`, `DEFDBL`, `DEFSTR` and `DEFSNG` apply to the parameters of the procedures after them in the source; untyped parameters were always SINGLE.
- **SUB Calls Starting with a Parenthesis**: `Name (a + 1) * 2, b` without `CALL` passes `(a + 1) * 2` as the first argument; the parentheses were taken to wrap the whole argument list (a syntax error). A SUB name is no longer read as an array first, which created a stray array and broke later calls such as `Name(5, 6)`.
- **PRINT USING (behavior change)**: Formats follow QBasic: literal text around fields is printed (`"t=##.##"` dropped the `t=`), each value fills the next field instead of being formatted with the whole format, and the format starts over when values outnumber its fields. Added `\  \` string fields, `,` thousands commas, `+` and `-` signs, `^^^^` exponents, `**`/`$$`/`**$`, `_` escapes and `%` on overflow; a string in a number field is "Type mismatch" and a format with no fields is "Illegal function call". C `printf` formats (`"%6.2f"`, `"%s"`) still work when the format has no QBasic fields, and are now checked first: a format such as `"%s"` given a number used to be passed straight to C and could crash.
- **Boing Ball at Full Resolution**: `demo/boing_ball.bas` draws in 1024x768 pixels instead of mapping a 640x480 layout with `WINDOW SCREEN`. The checker texture is drawn in 2-pixel bands (it was 3.2-pixel bands that overlapped and left stray pixels at the rim). Each of the 64 frames of the ball's spin is drawn the first time it is shown, into an 8x8 sprite sheet, and copied with `_PUTIMAGE` after that, so a frame takes well under a millisecond instead of about 22 ms. The motion follows elapsed time, so the ball keeps its speed while the first frames are drawn. It now runs at up to 60 frames per second (was 55), bounces about 40% higher and moves more slowly, with a floatier bounce.
- **Paint Scrolling**: When `demo/qb64_paint.bas` is made smaller than its picture, scroll bars appear around the picture area: drag a thumb, click a track to move a page, use the arrow keys, or draw past the edge to scroll toward the mouse. The thumbnail outlines the part in view.
- **SUB Calls Before a Colon**: `IF x THEN Name: ...` and `a = 1: Name: ...` call `SUB Name`; they were taken as a line label and skipped. `Name:` is still a label at the start of a line.
- **Function Suffixes**: A `FUNCTION` declared with a type suffix can be called without it, as in QB64 (`FUNCTION Mk&` as `Mk(0)` returned 0; `FUNCTION Greet$` as `Greet("x")`), and `Greet = ...` inside `FUNCTION Greet$` sets its result (it was lost). A different suffix is still a different name. `LEN` of a string `FUNCTION` call or of a string expression (`LEN(a$ + "xy")`) is the length of the whole value; it was 0, or the length of `a$` followed by a syntax error.
- **Resizable Window**: Added QB64's `$RESIZE:{ON|OFF|STRETCH|SMOOTH}` metacommand, the `_RESIZE [{ON|OFF}][, {_STRETCH|_SMOOTH}]` statement, and the `_RESIZE`, `_RESIZEWIDTH` and `_RESIZEHEIGHT` functions. With `$RESIZE:ON` the user can resize the window; `_RESIZE` returns -1 once per user resize, so the program can make a screen of the new size with `SCREEN _NEWIMAGE(_RESIZEWIDTH, _RESIZEHEIGHT, 32)` and redraw it. Added `demo/resize_demo.bas`. `demo/qb64_paint.bas` uses it too: its window can be resized (down to 560x560), the palette and thumbnail stay at the bottom and right edges, and the picture grows to fill a larger window, keeping what was drawn; a smaller window only hides the edges. Fixed: a QB64 function named alone as a `SUB` argument (`Show _PI`, `SetSize _RESIZEWIDTH, _RESIZEHEIGHT`) was passed as an empty by-reference variable, so the SUB received 0. A `_NEWIMAGE` screen 200 or 350 pixels tall is no longer shown at a forced 4:3 shape (only `SCREEN` modes are).
- **Array Parameters**: Arrays can be passed to a `SUB` or `FUNCTION` as `name()` and are shared with it (`SUB Show (values())`); previously the argument was evaluated as a number and the procedure saw an empty array. Added `LBOUND` and `UBOUND`.
- **QBasic Number Rules (behavior change)**: Array subscripts, `DIM` bounds and every other whole-number argument (string positions and lengths, `CHR$` codes, file numbers, `LOCATE`, `ON ... GOTO`, graphics coordinates, `PRINT USING` digits, ...) round like `CINT` (`a(1.5)` is `a(2)`, `CHR$(65.6)` is `B`) instead of truncating. `SQR` of a negative, `LOG` of zero or a negative, and fractional powers of negative numbers are "Illegal function call"; results too large for a DOUBLE (or a SINGLE variable) are Overflow; `0 ^ -1` is "Division by zero". Numbers print without a leading zero (`.5`) and with an uppercase `E` or `D` exponent, as in QBasic.
- **EQV, IMP, MKL$ and CVL**: Added the `EQV` and `IMP` operators (the loosest-binding, after `XOR`) and the LONG conversions `MKL$` and `CVL`. `MKI$` now rounds and reports Overflow. Functions with whole-number results (`LEN`, `LOF`, `CVL`, ...) print every digit.
- **Exact Integer Arithmetic (behavior change)**: Integer variables now hold exact 64-bit values instead of doubles, and expressions carry their QBasic type: an operation takes the larger operand type, and an INTEGER, LONG or `_INTEGER64` result that does not fit is an Overflow error (`a% * b%` with 200 and 200 overflows even when assigned to a LONG; use `CLNG`). `_INTEGER64` is exact over its whole range instead of only up to 2^53, and `_UNSIGNED _INTEGER64` arithmetic wraps. Whole-number literals beyond LONG range are `_INTEGER64`, `&H` literals can be 64 bits wide, comparisons between integers and floats are exact, and `PRINT`, `STR$`, `HEX$`, `OCT$`, `READ`, `INPUT`, `CONST`, record I/O and `COMMON` keep every digit. `FOR` loops with an integer counter count in integers, and stepping past the type's range is an Overflow as in QBasic.
- **CINT, CLNG, CSNG, CDBL**: Added the QBasic type-conversion functions (they returned 0). `CINT` and `CLNG` round half to even.
- **Operator Precedence (behavior change)**: Operators now follow QBasic precedence: `^` binds left to right and tighter than negation (`-2 ^ 2` is -4, `2 ^ 3 ^ 2` is 64), and `\` binds below `*` and `/` but above `MOD`. `^` in an assignment or `IF` condition was a syntax error.
- **One Expression Parser**: Statements that were parsed from their text now evaluate expressions with the same token parser as assignments and `IF`, removing a second, slightly different evaluator.
- **Integer Performance**: Integer `FOR` loops and arithmetic no longer convert through doubles or look up the variable type by name on every store, and programs with `DIM ... AS` declarations or procedures use the compiled expression cache. A 10-million-iteration loop with `&` variables runs in 0.77 s instead of 1.26 s, and the same loop with `DIM ... AS LONG` in 1.8 s instead of 3.3 s; the SINGLE benchmark is unchanged.
- **STR$ and DATA**: `STR$` formats numbers like `PRINT` (`STR$(1234567)` was `" 1.23457e+06"`). Unquoted `DATA` items are read as written, so words are strings instead of variable values.
- **Boing Ball**: `demo/boing_ball.bas` draws at 1024x768 again (its window had shrunk to 640x480 when it moved to a 32-bit `_NEWIMAGE` screen), keeping its 640x480 layout through `WINDOW SCREEN`, and shows a frames-per-second counter in the bottom-right corner.
- **Name Lookup Performance**: Whether a name is a `CONST` or a string variable is now remembered on each token instead of being looked up (with case-insensitive string compares) on every evaluation. Programs with constants or `DIM ... AS` declarations run much faster: the Boing Ball renders 90 frames in 2.9 s instead of 5.1 s headless, and a 10-million-iteration `DIM ... AS LONG` loop takes 1.4 s.
- **Audio Start-up**: Programs that use `PLAY` or `SOUND` open the audio device when they start, so the first sound no longer pauses the program for about a quarter second (the first bounce in `demo/boing_ball.bas` was late).
- **Error Messages in Graphics Mode**: Untrapped errors are also written to stderr while a graphics screen is open, since the window may be hidden (`--headless`) or close right away.
- **Fixes**: `SWAP` inside a `SUB` or `FUNCTION` swapped module-level variables instead of the locals, and accepted variables of different integer types. Cached expressions no longer treat `CSRLIN`, `POS` or QB64 functions written without parentheses as variables. `demo/boing_ball.bas` no longer takes `SQR` of a slightly negative number at the rim of the ball.
- **Paint Demo**: Added `demo/qb64_paint.bas`, an interactive MacPaint-style program using `_NEWIMAGE`, `_DEST`, `_PUTIMAGE` (scaled thumbnail, mirror and flip), `_COPYIMAGE` undo, `_MOUSEX`/`_MOUSEY`/`_MOUSEBUTTON`/`_MOUSEWHEEL`, `_KEYHIT`/`_KEYDOWN`, `_RGBA32` opacity and `_PRINTWIDTH`. `--selftest` draws a sample picture and saves `basika_paint_selftest.png`.
- **RESTORE label**: `RESTORE` accepts a line label as well as a line number, including from inside a `SUB` or `FUNCTION`; an unknown label is "Undefined line number".
- **Procedure Call Fixes**: A procedure call inside another call's arguments (`Outer(Inner(x), y)`) no longer overwrites the outer call's frame. A `SUB` called from inside a `FUNCTION` no longer ends the `FUNCTION` early. Passing a `FUNCTION` name as an argument passes its result instead of creating a by-reference variable of that name.
- **Off-screen Images**: `_NEWIMAGE(w, h[, mode])` returns an image handle; `_DEST` and `_SOURCE` redirect all drawing (including `PRINT`, `PAINT` and `CLS`) and all reading (`POINT`, `GET`); `_PUTIMAGE` copies between any images in QB64's argument order, keeping size, stretching or mirroring, with alpha blending for 32-bit images; added `_COPYIMAGE`, `_WIDTH(handle)`/`_HEIGHT(handle)` and `SCREEN handle`. Images loaded with `_LOADIMAGE` can be drawn on.
- **Image Handles (behavior change)**: Image handles now follow QB64: valid handles are below -1, `_LOADIMAGE` returns -1 on failure (it returned 0), and 0 means the screen. `POINT` on a 32-bit image returns the stored alpha.
- **QB64 Input and Window**: Added `_TITLE`, `_KEYDOWN`, `_KEYHIT`, `_MOUSEX`, `_MOUSEY`, `_MOUSEBUTTON`, `_MOUSEINPUT` and `_MOUSEWHEEL` with QB64 key codes.
- **QB64 Types**: Added `_BYTE`, `_INTEGER64`, `_UNSIGNED INTEGER`, `_UNSIGNED _BYTE` and `_UNSIGNED _INTEGER64` (suffixes `%%`, `&&`, `~%`, `~%%`, `~&&`), including `TYPE` fields with their packed record sizes, and `DEFLNG`.
- **Graphics Showcase**: The static sky is now drawn once into an off-screen image and copied each frame with `_PUTIMAGE`.
- **Line and Character Input**: Added `LINE INPUT [;] ["prompt";] [#n,] var$`, `INPUT$(n[, [#]file])`, and `WRITE [#n,] list`. `INPUT` now accepts quoted values containing commas, honors `DIM ... AS STRING` variables, and from the keyboard re-asks with `?Redo from start` when the values do not match.
- **CLEAR and WIDTH**: `CLEAR` zeroes variables and arrays, empties strings, closes files and resets the GOSUB/FOR stack while keeping `CONST`s, `TYPE`s and `DEF FN`s. `WIDTH columns[, rows]` re-lays the text grid (40/80 by 25/30/43/50/60); file and device widths are accepted.
- **PALETTE and Pages**: `PALETTE attribute, color`, `PALETTE` and `PALETTE USING array(start)` change palette entries and recolor pixels already on screen (VGA 0-63 RGB values in SCREEN 12/13, EGA values in SCREEN 0/9). `SCREEN mode, , apage, vpage` selects drawing and display pages (8 in SCREEN 0/7, 4 in 8, 2 in 9) and `PCOPY` copies pages, for double buffering.
- **CHAIN and COMMON**: `CHAIN file$` runs another program, passing `COMMON` variables (scalars, strings and arrays) by position and keeping files open; `COMMON SHARED` also shares them with procedures.
- **LOCK and UNLOCK**: Whole-file, record and record-range locks use operating-system advisory locks, so another process's lock is "Permission denied". Added `ERDEV`/`ERDEV$` (always 0 and "").
- **PEN and STICK**: `PEN(n)`, `ON PEN GOSUB` and `PEN ON/OFF/STOP` treat the mouse as a light pen; `STICK(n)` reads joysticks through SDL, and joystick buttons now drive `STRIG` and `ON STRIG` traps (which were never triggered before).
- **Editing Commands**: Direct mode adds `SAVE`, `LOAD [, R]`, `MERGE`, `RENUM` (updating `GOTO`/`GOSUB`/`THEN`/`ELSE`/`RESTORE`/`RESUME`/`RUN` targets and `ON ... GOTO` lists), `AUTO` and `EDIT`. They are recognized only as direct-mode commands, so they remain usable as variable names.
- **STATIC**: `SUB ... STATIC` keeps all of its locals, arrays and records between calls, and the `STATIC name[()] [AS type]` statement keeps the listed ones (it was a syntax error). `SHARED` now works inside a `FUNCTION` called from an expression.
- **Local Record Arrays**: Arrays of records `DIM`med in a procedure are local, may reuse a module array's name, and may take different bounds on each call. Call frames grow on demand beyond the old 128-local limit.
- **STOP, CONT and Direct Mode**: `STOP` and Ctrl+C pause with `Break in N`, and `CONT` resumes with loops and `GOSUB`s intact ("Can't continue" after an edit). Direct-mode lines now run through the program's statement loop, so colons, one-line loops and `GOSUB` work and `GOTO` continues into the program; errors there show no line number. Added `LIST first-last` ranges, `RUN line`, and deleting a line by typing its number alone.
- **WAIT**: Added `WAIT port, and[, xor]` with a simulated 60 Hz VGA retrace on `&H3DA`, so `WAIT &H3DA, 8` paces animation; other ports read 0.
- **Random and Binary Files**: `OPEN` accepts `LEN = reclen`, `APPEND` and `BINARY` modes, `AS n` without `#`, `ACCESS`/lock clauses, and the GW-BASIC `OPEN "R", #1, f$, len` form. RANDOM files no longer truncate when reopened, and records sit at `(n - 1) * LEN` (default 128); a `TYPE` larger than `LEN` is "Bad record length", a `FIELD` larger than `LEN` is "FIELD overflow", record numbers below 1 are "Bad record number", and reopening an open file number is "File already open". `PUT`/`GET` without a record number use the next record, `LOC` returns the last record (or byte for BINARY), and `CLOSE` accepts several or no file numbers.
- **Division (behavior change)**: Division by zero is now the "Division by zero" error instead of silently returning the left operand, and `\` and `MOD` round their operands to whole numbers first (`5.9 \ 2` is 3), as in QBasic. A statement whose expression fails no longer prints or assigns the failed value.
- **Bug Fixes**: A `SUB` called without `CALL` after `THEN`, `ELSE`, or a colon received the wrong arguments (the line was re-read from its start). String comparisons now combine with `AND`, `OR`, and `NOT` (`IF a$ <> "" AND a$ <> " " THEN`) instead of being a syntax error. `SYSTEM` and `QUIT` now end a running program instead of reporting a syntax error. Arrays `DIM`med in a `SUB` or `FUNCTION` are local and created on every call (previously the second call failed with "Duplicate Definition"); `ERASE` and graphics `GET`/`PUT` act on those local arrays. A single-line `FOR ... NEXT` inside a `FUNCTION` no longer loops forever. Fixed-length string `TYPE` fields and `STRING * n` variables written in lowercase now work in `PRINT`, comparisons, and `LEN`, including elements of record arrays, and `SHARED name() AS type` reaches record fields.
- **QBasic Numeric Semantics (behavior change)**: Unsuffixed decimal literals with more than 7 significant digits are now DOUBLE instead of being rounded to single precision (`E` exponents and `!` still mean SINGLE). Assigning to INTEGER and LONG variables now rounds half to even (`I% = 10.5` gives 10, `11.5` gives 12) instead of half away from zero.
- **Variable Limit**: The variable table now holds 8192 variables (was 1024), so arrays of a thousand records fit. Procedure calls clear only the lookup-cache entries they used instead of the whole call frame, which also makes calls faster (200,000 `SUB` calls: 0.17 s to 0.11 s).
- **QBASIC Graphics Syntax (breaking)**: `PSET`, `PRESET`, `LINE`, `CIRCLE`, and `PAINT` now take QBasic argument lists. `CIRCLE` adds `start`/`end` arc angles (negative angles draw pie-wedge radius lines) and `aspect` ellipses, with QBasic's default aspect so circles look round in 200- and 350-line modes; its old fill argument is gone, so fill shapes with `PAINT`. `LINE` adds the 16-bit `style` mask, `PAINT` adds tile strings and the `background$` argument, and every primitive accepts `STEP(dx, dy)` relative coordinates and empty arguments. Primitives without a color use the `COLOR` foreground, `PRESET`/`CLS` use the background, `POINT(2)`/`POINT(3)` return logical coordinates, and outlines are rasterized pixel by pixel so each pixel is drawn once. The old trailing alpha arguments were removed; demos and tests were updated.
- **QB64 32-bit Color and Alpha**: `SCREEN _NEWIMAGE(w, h, 32)` creates a 32-bit image whose colors are `&HAARRGGBB` values; translucent colors blend in every primitive, including `PAINT`. Added `_RGB32`, `_RGBA32`, `_RGB`, `_RGBA`, `_RED32`/`_GREEN32`/`_BLUE32`/`_ALPHA32`, `_RED`/`_GREEN`/`_BLUE`/`_ALPHA`, `_PI`, `_WIDTH`, and `_HEIGHT`. `PAINT` inside a `VIEW` reads back only the view.
- **Timing (breaking)**: `SLEEP` now takes seconds and wakes on a key press as in QBasic; `SLEEP` with no argument waits for a key. Added `_DELAY seconds` and `_LIMIT fps`. `TIMER` now returns wall-clock seconds since midnight instead of CPU time.
- **Typed Declarations**: Added `DIM name AS INTEGER | LONG | _UNSIGNED LONG | SINGLE | DOUBLE | STRING` for scalars and arrays, `DIM SHARED`, `lower TO upper` array bounds, typed `SUB`/`FUNCTION` parameters that convert their arguments, `SHARED name AS type`, and `LONG`/`_UNSIGNED LONG` `TYPE` fields (4 bytes in records). Added the `&` (LONG) and `~&` (_UNSIGNED LONG) suffixes.
- **Numeric Literals**: Added `&H`, `&O`, and `&B` literals with QBasic INTEGER/LONG typing; whole-number literals are now exact; `HEX$`/`OCT$` print 32-bit values; `AND`/`OR`/`XOR`/`NOT` keep all bits of LONG values.
- **Fixes**: String parameters and locals of `SUB`/`FUNCTION` calls are now released when their call frame is reused; previously each call leaked a string-pool slot until the 2048-slot pool ran out and string expressions failed with a misleading "Syntax error" (the showcase demo hit this after about 12 seconds). The pool now falls back to the heap when full. `LEN` of a string local or parameter inside a procedure returned the length of the module-level variable of the same name instead. `CONST` names passed to procedures are passed by value instead of as empty variables; statements after `CASE ELSE:` on the same line now run; `RESUME label` works; `WINDOW` without a prior `VIEW` maps coordinates correctly; `PUT` honors the `AND`, `OR`, and `XOR` actions.
- **Interpreter Performance**: The run loop no longer copies each statement's first token, cutting the `basica.bas` benchmark from about 1.04 s to 0.78 s on the same machine.
- **Graphics Showcase**: Rewrote `demo/graphics_primitives_showcase.bas` as an animated 32-bit scene (aurora, RGB alpha orbs, a ringed planet built from `CIRCLE` arcs, a comet with particle sparks, and cards demonstrating pie wedges, `LINE` styles, `PAINT` tiles, and alpha) written with `CONST`, `TYPE`, `DIM SHARED`, typed procedures, `_RGBA32`, and `_LIMIT`. Converted `boing_ball.bas` to a 32-bit image with an `_RGBA32` shadow.
- **QBASIC `CONST`**: Added the `CONST name = expression` statement for declaring named numeric constants. Constants can be used in numeric expressions, array dimensioning, `FOR` loop bounds, and `DEF FN` bodies; they are resolved at runtime so they may reference variables in scope at execution time. Constants are cleared on `RUN` and `NEW`. Added test coverage.
- **QBASIC `POINT`**: Added `POINT(x, y)` to read the palette color index of a pixel and `POINT(0)`/`POINT(1)` to read the last graphics cursor X/Y coordinate. Implemented as an identifier-level function (not a keyword) to avoid conflicts with identifiers like `Point`. Returns -1 for out-of-bounds coordinates and 0 for `POINT(n)` with n outside 0/1. Added test coverage.
- **QBASIC `CSRLIN` and `POS(n)`**: Added `CSRLIN` to return the current text cursor row (1-based) and `POS(n)` to return the current text cursor column (1-based). The `n` argument is accepted but ignored per QBASIC specification. Added text cursor row (`print_row`) tracking to the interpreter and `get_text_cursor()` to the graphics subsystem. Added test coverage.
- **CONST/Point Performance**: Added an early-out guard in the named-constant lookup (`find_named_constant`) that skips string normalization when no constants are defined, keeping the 10-million-iteration BASICA benchmark at its prior ~0.59-second baseline.
- **Statement and Procedure Lookup Performance**: The run loop now advances to the next statement via the program list instead of rescanning from the first line after every statement, and expression evaluation caches each identifier's procedure lookup on its token (invalidated whenever procedures are rescanned). `boing_ball.bas` frame rendering dropped from about 88 ms to 34 ms (headless), and the `basica.bas` benchmark improved from about 1.10 s to 1.04 s on the same machine.

## 0.99.6 — 2026-10-03

- **QBASIC `SELECT CASE`**: Added the full `SELECT CASE ... END SELECT` block construct, supporting `CASE value1[, value2...]` value lists, `CASE value1 TO value2` inclusive ranges, `CASE IS comparison-op value` comparisons (`=`, `<>`, `<`, `>`, `<=`, `>=`), and a catch-all `CASE ELSE`. Multiple comma-separated items may be combined within a single `CASE` clause. Works with both numeric and string expressions, only the first matching branch executes, and it supports arbitrary nesting (including within `IF`, `FOR`, `WHILE`, and `DO` blocks) and use inside `SUB`/`FUNCTION` procedures.
- **SELECT CASE Regression Coverage**: Added tests covering single values, comma-separated value lists, `TO` ranges (including overlapping-range first-match semantics), all six `CASE IS` comparison operators, `CASE ELSE`, string `SELECT CASE`, nested `SELECT CASE`, `SELECT CASE` inside `SUB`/`FUNCTION` procedures, and `SELECT CASE` inside a loop with `EXIT DO` from within a `CASE` branch.
- **QBASIC `DO...LOOP`**: Added the full `DO...LOOP` block construct, including the infinite `DO ... LOOP` form, pre-test `DO WHILE`/`DO UNTIL` conditions, and post-test `LOOP WHILE`/`LOOP UNTIL` conditions. Supports `EXIT DO` to break out of the innermost loop, arbitrary nesting (including within `IF`, `FOR`, `WHILE`, and other `DO` blocks), and use inside `SUB`/`FUNCTION` procedures.
- **DO...LOOP Regression Coverage**: Added tests covering every loop variant, nested `DO` loops, `EXIT DO` scoping to the innermost loop, and `DO...LOOP` inside procedures.
